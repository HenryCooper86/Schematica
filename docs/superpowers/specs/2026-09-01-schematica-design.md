# Schematica — Design Spec

**Date:** 2026-09-01
**Status:** Approved by user (design review in chat)

## What

Schematica is a browser-based canvas board for drawing embedded-system and
hardware architecture diagrams, in the spirit of
[net_draw](https://mr-r3b00t.github.io/net_draw/) but specialized for embedded
hardware: microcontrollers, sensors, actuators, power, and connectivity,
joined by **typed bus connections** (I2C, SPI, UART, CAN, power rails, …).

It is a static site: no framework, no build step, no server. It runs on
GitHub Pages or any static host, and locally via any static file server.

## V1 scope

In: component palette, drag-to-canvas nodes with ports, typed wires, zones,
sticky notes, inline label editing, properties panel, pan/zoom, grid snap,
marquee/multi-select, undo/redo, duplicate, localStorage autosave, save/open
JSON, SVG and PNG export, bus-color legend.

Out (YAGNI, explicitly deferred): recording/GIF export, presentation/journey
mode, real-time collaboration, auto-layout, pin-level netlists, BOM export.

## Architecture & files

```
Schematica/
  index.html          — shell: toolbar, palette sidebar, SVG canvas, properties panel
  css/style.css
  src/
    main.js           — boot, wires modules together, event plumbing
    state.js          — document model + undo/redo (single source of truth)
    render.js         — draws model into layered SVG (grid / zones / wires / nodes / overlay)
    tools.js          — pointer state machine: select, wire, zone, note, pan
    palette.js        — component library definitions (pure data)
    buses.js          — bus type definitions (pure data)
    serialize.js      — save/load JSON, schema validation, versioning
    export.js         — SVG and PNG export
    geometry.js       — pure math: port positions, hit tests, wire paths, snapping
  tests/              — node:test unit tests for state, serialize, geometry
```

Principles:

- JS loaded natively via `<script type="module">`; no npm dependencies at
  runtime, no bundler.
- The model in `state.js` is the single source of truth. UI events mutate the
  model through named actions; `render.js` redraws the affected SVG layers
  from the model. The DOM is never the source of truth.
- `palette.js`, `buses.js`, `geometry.js`, `serialize.js`, and the mutation
  logic in `state.js` are pure (no DOM access) so they run under Node's
  built-in test runner with zero tooling.

## Data model

One JSON document:

```json
{
  "schema": 1,
  "title": "My Board",
  "nodes":  [{ "id": "n1", "kind": "mcu", "x": 100, "y": 80, "w": 160, "h": 100,
               "label": "MCU", "sublabel": "STM32F4", "color": null }],
  "wires":  [{ "id": "w1", "bus": "i2c",
               "from": { "node": "n1", "port": "i2c" },
               "to":   { "node": "n2", "port": "i2c" },
               "label": "" }],
  "zones":  [{ "id": "z1", "x": 40, "y": 40, "w": 400, "h": 300,
               "label": "Sensor board", "color": "#4a90d9" }],
  "notes":  [{ "id": "t1", "x": 500, "y": 60, "text": "3.3V domain" }]
}
```

- `kind` references a palette definition, which supplies default size, glyph,
  and **ports** — named connection points on the node edge, each with a
  suggested bus type.
- Wire `label` defaults to the bus's short name at the wire midpoint; the
  user can edit it.
- IDs are short unique strings generated by `state.js`.
- Undo/redo: snapshot stack of structural clones, pushed per committed action
  (drag end, not every mousemove). Capped (e.g. 100 entries).

## Component palette (v1)

Sidebar with collapsible categories; click or drag a part onto the canvas.

- **Compute:** MCU, SoC/SBC, FPGA, DSP
- **Sensors:** temperature, IMU, GPS, camera, ADC input, generic sensor
- **Actuators:** motor + driver, servo, relay, LED, display (OLED/LCD), buzzer
- **Power:** battery, regulator (LDO/buck), charger, solar panel, power jack
- **Connectivity:** WiFi/BLE module, LoRa, cellular, Ethernet PHY, USB port,
  CAN transceiver, RF antenna
- **Storage/Misc:** EEPROM/Flash, SD card, RTC, crystal, debug header
  (JTAG/SWD), generic IC, custom box

Rendering: rounded rect, small vector glyph, title (label), editable sublabel
(part number). Ports are small circles on the node edge; hovering highlights
them and shows the port name.

Each palette entry defines: `kind`, category, default `w/h`, glyph, default
label, and `ports: [{ id, name, side, offset, bus }]` (side = top/right/
bottom/left, offset = fraction along that side).

## Bus types & styling

| Bus | Style |
|-----|-------|
| I2C | solid, distinct color |
| SPI | solid, distinct color |
| UART | solid, distinct color |
| CAN | solid, distinct color |
| USB | solid, distinct color |
| Ethernet | solid, distinct color |
| GPIO | thin neutral |
| PWM | dashed variant |
| ADC/analog | dashed variant |
| RF | dotted |
| Power | thick red |
| GND | thick black, dashed |

Exact colors chosen at implementation time for contrast on the canvas
background in both light and dark themes. A toggleable legend box explains
the mapping. Wires render as smooth curves (cubic bezier leaving each port
perpendicular to its node edge), with the label at the midpoint.

## Interactions

Tools (toolbar buttons + shortcuts):

- **V** — select/move: click select, drag move, marquee select empty-space
  drag, shift-click add to selection, multi-drag.
- **C** — wire: drag from a port, live rubber-band, drop on a target port.
  On drop, a small popover picks the bus type (defaulting from the ports'
  suggested types; if both ports agree, no popover — it just uses that type).
  Dropping anywhere invalid cancels.
- **Z** — zone: drag a rectangle; zones render behind nodes with a translucent
  fill and a title.
- **N** — note: click to place a sticky note.
- **Space**-drag or middle-mouse — pan. Scroll wheel — zoom, centered on the
  cursor. Zoom indicator with reset in the toolbar.
- **Delete/Backspace** — delete selection (wires attached to a deleted node go
  with it). **Ctrl/Cmd-Z** undo, **Ctrl/Cmd-Shift-Z** redo, **Ctrl/Cmd-D**
  duplicate selection.
- Double-click a node title/sublabel, wire label, zone title, or note to edit
  inline (contenteditable overlay positioned over the SVG text).
- Grid: 8 px snap for node positions and zone rects, toggleable in toolbar.
- Properties panel (right side): shows editable fields for the current
  selection — label, sublabel, color for nodes; bus type + label for wires;
  label + color for zones; text for notes. Hidden when nothing is selected.

## Persistence & export

- **Autosave:** serialize to `localStorage` after every committed action;
  restore on page load. "New" button clears the board (with confirm).
- **Save:** download `<title>.schematica.json`.
- **Open:** file picker; validated before replacing the current document.
- **Export SVG:** serialize zones/wires/nodes/notes layers (not grid or
  selection overlay) into a standalone SVG with embedded styles, tightly
  cropped to content bounds plus margin.
- **Export PNG:** render the export SVG to an offscreen canvas at 2× and
  download.

## Error handling

- `serialize.js` validates on load: required arrays present and well-typed;
  wires must reference existing node ids/ports (dangling wires dropped with a
  warning count); unknown node `kind` falls back to a generic box preserving
  label/position; unknown `bus` falls back to GPIO. A malformed file is
  rejected with a readable message and leaves the current document untouched.
- `schema` field enables future migrations; loading a newer schema than we
  know warns but attempts a best-effort load.
- localStorage read wrapped in try/catch; corrupted autosave is discarded
  (with a console warning), never a boot crash.

## Testing

- **Unit (node:test, zero deps):**
  - `state.js`: every mutation action; undo/redo including stack cap;
    duplicate; delete cascading to attached wires.
  - `serialize.js`: round-trip fidelity; each malformed-input rejection and
    fallback path.
  - `geometry.js`: port absolute positions per side/offset; hit testing;
    snapping; wire path endpoints.
- **Manual in-browser:** interaction flows (wire drawing, marquee, zoom/pan,
  inline editing, export outputs opened and eyeballed).

## Success criteria

A user can open the page, drag out an MCU + a few peripherals, wire them with
correctly colored typed buses, group them in zones, save the JSON, reload it,
and export a clean SVG/PNG — with no console errors, working undo throughout.
